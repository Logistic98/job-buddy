# 评估用例格式与覆盖范围

本目录统一使用 YAML。所有套件采用相同公共字段，`kind` 决定执行方式，不能把校准、规格校验和真实效果通过率混算。

## 目录与执行边界

| 文件 | kind | 用例数 | 评估范围与执行方式 |
| --- | --- | ---: | --- |
| runtime-engine.yaml | runtime | 26 | Hint、Planner、联网证据、代码执行、简历切换；直连 Runtime |
| runtime-regression.yaml | runtime | 38 | 路由、联网许可、上下文、附件隔离、输出格式、沙箱计算；直连 Runtime |
| runtime-observability.yaml | runtime | 3 | 模型用量、工具耗时、过程事件；直连 Runtime |
| grader-calibration.yaml | calibration | 46 | 评分正反例、权限与预算终止、Checkpoint、证据和数值边界；离线评分 |
| business-job.yaml | business | 36 | 求职、登录、筛选、缺失数据、属主隔离、记忆与恢复；业务端或人工验收规格 |
| memory-baseline.yaml | memory | 32 | 28 个单事实/多事实检索、4 个显式更新；真实记忆引擎执行 |

业务规格中的 `expected.outcomes` 是待核验的用户可见结果，格式校验不会执行登录或业务事务。Memory runner 还执行跨用户/租户隔离和生命周期检查，固定协议列在 `contracts`；这些代码检查不计入表中的数据驱动用例数。Memory 的显式更新不代表模型自动抽取或自然语言纠错已被评估。

## 公共结构

```yaml
schema_version: 1
id: runtime-example
version: 1
name: 示例评估集
description: 验证逐字输出及无工具执行边界。
kind: runtime
defaults:
  runtime_profile: job-buddy
fixtures: {}
contracts: {}
cases:
  - id: exact_output
    category: output_contract
    description: 保留数字字符串的前导零。
    input:
      message: 只原样输出 00042，不解释。
    expected:
      answer_equals: '00042'
      expect_no_tool_results: true
      events: [done]
    options:
      suite: regression
    rubric: 不添加解释、引号或其他字符。
```

`schema_version` 是格式版本，`version` 是数据集版本。改变任务或预期标签时更新数据集版本，不能为了当前评估通过降低阈值。用例身份为 `套件 id / 用例 id`；套件 ID 在目录内唯一，用例 ID 在套件内唯一。不同层可以针对同一场景使用相同用例 ID。

每个用例必须包含 `id/category/description/input/expected`。`input` 和 `expected` 均为对象；`options` 放执行条件、预算等设置；`rubric` 放需要 Judge 或人工判断的标准。描述写验证目标，预期写可观察的正确结果，不在说明里隐藏应当执行的断言。未知字段、重复 YAML 键、错误类型、错误事实引用和非法预算会被拒绝。

## 各类输入与期望

| kind | input | expected | defaults / fixtures |
| --- | --- | --- | --- |
| runtime | `message`；可选 `messages/metadata/session_id` | 结构化路由、事件、工具证据、答案等断言 | 默认 Profile/时延；不使用共享运行结果 |
| calibration | `run_overrides/metrics/events`；可选 `error/judge` | `passed` 是预先标注标签；`checks` 是待测断言；`issue_codes` 可锁定失败原因 | `fixtures.run` 提供基础运行；run_overrides 仅覆盖顶层字段 |
| business | `message`；上下文放 `metadata/messages` | `outcomes` 必填，其他字段为业务契约 | 前置条件放 `options.preconditions` |
| memory | `operation: search/update`、`query`；更新再提供 `fact_id/content` | 检索用 `ids`；更新用 `content/previous_content_absent` | `fixtures.facts` 是合成事实；`defaults.thresholds` 是固定指标门槛 |

Runtime 声明 `messages` 时以完整消息序列构造请求，`message` 保留为任务说明。需要后台准备的登录、简历与岗位条件写入 `options.preconditions`，条件不满足会跳过；它不会自动准备数据。Boss 用例标记 `options.requires_live_boss: true`。校准标签只验证规则判定，不宣称合成数据已被真实服务执行。

Memory 先执行全部检索，再执行更新；文件中按同样顺序排列。`expected.ids` 必须引用现有事实 ID，更新预期内容必须与输入一致且明确排除旧内容。阈值包含 Recall@5、MRR@5、更新/隔离/生命周期正确率及检索/更新 p95，不允许空阈值使评估空跑通过。

## 校验和运行

在 agent-eval 目录执行：

```bash
# 自动发现并校验所有类型，打印分类覆盖；无网络调用
$ uv run python scripts/validate_cases.py

# 只执行预先标注的评分器校准集
$ uv run python -m pytest tests/graders/test_grader_calibration.py -q

# 真实 Runtime 回归；服务必须已启动
$ uv run python scripts/run_engine_eval.py --cases cases/runtime-regression.yaml \
  --category output_contract,multi_turn --repeats 3
```

Memory 的真实执行入口保持为 `agent-memory/scripts/evaluate_memory.py`，默认读取本目录的 memory-baseline.yaml。需要配置真实模型和独立评估存储；格式校验与确定性测试不能证明真实检索效果达标。完整门禁见模块 README。
