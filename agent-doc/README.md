- 首次了解项目时，建议先阅读 [系统架构与核心链路](架构设计/系统架构与核心链路.md)，再根据关注点进入核心能力或业务专题。

## 文档职责与维护

- 根 `README.md` 只负责项目介绍和快速开始，模块 README 只负责该模块的入口、接口、启动与验证，`agent-doc` 主题文档负责跨模块设计和业务规则。
- 重复内容应保留在最接近事实源的文档中，其他位置使用摘要和链接，避免同一默认值、流程或安全策略多处独立维护。

- 主题文档以代码、配置、迁移和测试为事实来源，说明正式方案、模块接口、异常与安全边界及验证方法，不记录迭代过程、路线图、真实密钥、个人数据或容易过期的手工快照。
- 内容按主题分段，每段只表达一个中心；
- 同类字段适合用表格，存在三步以上依赖关系时再使用图。
- Mermaid 统一采用基础 `graph LR`、`graph TD` 或 `sequenceDiagram` 语法，不依赖新版布局、图标和交互指令。
- 同一流程出现在多个文档时，以最接近代码事实源的主题文档为权威来源，其他文档复用同一份 Mermaid 源码，不另行改写节点、方向或分支含义；
- 配色与渲染约束见 [Markdown 内容渲染规范](工程规范/Markdown内容渲染规范.md)。

- 接口、配置、端口、职责、存储或用户流程变化时，应同时检查主题文档、相关模块 README、根 README、`.env.example`、Harness 和 Eval。
- 提交前必须校验 Markdown 围栏、本地链接、Mermaid 语法和 `git diff --check`。
