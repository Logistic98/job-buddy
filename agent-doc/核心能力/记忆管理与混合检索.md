# 记忆管理与混合检索

## 记忆边界

- 系统把信息分为当前步骤、当前任务、跨任务长期记忆和跨会话语义信息。
- 消息、`ChatSessionState` 与 Checkpoint 承载当前会话；
- 只有稳定偏好、约束、面试复盘和用户明确保存的内容才能进入长期库。
- 短期观察不能无筛选写入，召回内容也不能覆盖当前会话中的明确事实。

对话自动沉淀必须经过长期价值门控：只有能够在后续跨任务中复用的身份信息、长期求职目标、岗位与工作方式偏好、明确排除条件以及结构化面试复盘才允许写入。判断必须同时识别稳定主体和长期属性，不能因为文本中孤立出现“不要”“目标”“希望”“优先”等词就写入。输出格式、Markdown、Mermaid、LaTeX、代码示例、工具使用、页面渲染、当前文件或当前岗位分析等一次性任务指令只属于当前会话，即使包含上述词也不得自动沉淀。用户在设置页手动新增或用明确记忆命令保存内容仍视为用户授权的显式写入。

价值门控在对话写入器和设置服务的自动写入入口执行同一规则，前者减少无效调用，后者防止其他调用路径绕过；拒绝自动沉淀不能阻断正常问答，也不能影响显式新增、更新和删除。

- `agent-memory` 是用户长期记忆正文的唯一存储。
- 平台设置页和对话自动捕获都由 Backend 的 `AgentMemoryClient` 调用 `/v1/memories`；
- Backend 的 `platform_setting/global/settings` 只保存启用、自动保存、自动使用和容量上限等策略。
- 历史 `user-memory:*` 记录在用户首次访问时迁入 Memory，全部写入成功后才删除旧记录。

- Runtime 在 `ContextAssembler` 中检索 `long_term` 引用。
- 独立 Runtime 配置默认关闭记忆，完整本地栈通过根 `.env.example` 显式开启。
- Runtime 检索总超时默认为 15 秒，用于覆盖 Mem0 检索与 Embedding 调用预算；检索超时、连接失败或响应非法时以空引用继续；
- 设置页的显式写入、删除和清空失败则直接报错，不能写入 Backend 副本。

| 调用或存储路径                 | 正式行为                                                              | 失败边界                                 |
| ------------------------------ | --------------------------------------------------------------------- | ---------------------------------------- |
| Backend 列表、检索             | 独立连接 2 秒、读取 10 秒超时；只重试连接/读取异常、408、429 和 5xx   | 401、403、404 不重试，也不计入可用性熔断 |
| Backend 创建、更新、删除、清空 | 直接调用 Memory                                                       | 写入结果可能有歧义，失败后不自动重放     |
| 全部 scope                     | 统一使用 agent-memory；已配置 PostgreSQL 时必须使用 PostgreSQL 事实源 | 数据库故障不得动态切换到进程内存         |

正式服务必须配置 pgvector；进程内 Qdrant 仅通过测试或评估脚本显式构造。缺少配置时启动失败。

## Mem0 引擎与检索

记忆引擎统一使用锁定版本 `mem0ai==2.2.1` 的 OSS `Memory`。服务只负责鉴权、HTTP 契约和生命周期适配，不再维护自研 BM25、向量相似度或 RRF 实现。Mem0 负责 Embedding、存储、召回、排序、显式更新和历史记录。正式存储使用 PostgreSQL + pgvector；Mem0 自带的 SQLite history 必须挂载持久卷，服务采用单实例，备份同时包含向量库与 history。测试使用 Mem0 原生进程内 Qdrant，不允许正式服务在故障时切换到测试存储。

`POST /v1/memories` 保存调用方已经通过长期价值门控的事实，使用 `infer=false` 保持正文和单条响应契约；不把一条显式新增静默拆成多条。现有 HTTP 契约不提供自动抽取接口，自动保存入口的价值门控仍由 Backend 负责；不能把本次显式存储和检索评估解释为模型自动抽取质量。记忆身份由受信请求头构造，租户与操作者组合为 Mem0 user_id，scope 同时参与检索过滤。更新、删除和回滚必须先按所有者查询，禁止仅凭 ID 调用引擎。

秒级 TTL 保存在数值 metadata 中并在引擎查询前过滤；Mem0 原生 expiration_date 为日期粒度，不用于代替秒级契约。禁用条目在候选检索之前过滤。公开 ID 保持 `mem_` 前缀以兼容 Backend。默认搜索 Top-K 为 10，模型超时与重试有界，失败返回明确的 503，Runtime 可按原有契约降级为空引用。不得故障后返回自研排序结果并冒充 Mem0 成功。

模型地址、密钥、模型名、向量维度和 history 路径通过根目录环境配置注入。关闭 Mem0 telemetry。只向配置的模型供应商发送合成评估数据或已经授权处理的记忆。历史数据迁移必须显式执行、保留源表、逐条验证，禁止清空旧数据后重新初始化。

## 效果评估与交付指标

采用版本化的合成中文求职记忆集，包含同义改写、相近事实干扰、城市与薪资更新、不同租户同名用户、不同用户、禁用与 TTL。数据集与阈值先固定，不能按本次结果修改标签或降低门槛。每次运行保存 run_id、Git SHA、数据集 SHA256、mem0 版本、模型、向量后端、逐例命中与耗时、汇总和失败原因。评估使用独立身份分区，完成后清理自己的数据，禁止操作真实用户记忆。

| 指标 | 基线门槛 | 计算与边界 |
| --- | --- | --- |
| Recall@5 | ≥ 0.90 | 每个查询预期事实在前 5 条中的召回率宏平均 |
| MRR@5 | ≥ 0.85 | 首个正确事实排名倒数的宏平均，未命中为 0 |
| 事实更新正确率 | 1.00 | 显式更新后查询返回新事实且不返回旧事实 |
| 隔离正确率 | 1.00 | 跨用户、跨租户查询及更新/删除/回滚均不能访问目标事实 |
| 生命周期正确率 | 1.00 | 禁用/过期不召回，删除不可见，回滚恢复正确正文 |
| 检索 p95 | ≤ 3000 ms | 串行实测，包含查询 Embedding 和存储调用；至少 20 次 |
| 显式更新 p95 | ≤ 5000 ms | 包含真实 Embedding 与存储更新 |

确定性测试使用真实 Mem0 SDK 与受控 Embedding/LLM 替身，验证接口、过滤、生命周期和评估器判分；报告必须标注 `deterministic`，不构成效果达标证据。真实模型评估必须标注 `live`，禁止模型替身；依赖缺失、请求失败、样本不足或指标不达标均非成功。真实模型搭配本地 Qdrant 的结果只证明该组合，不替代生产 pgvector 验收。自动抽取及自然语言纠错另列指标，不以显式 PUT 的更新正确率冒充模型自动纠错能力。

## 生命周期与安全

- 记忆模型包含 `kind`、`scope`、`source`、`enabled`、operator、version 和 TTL。
- 工作台固定使用 `scope=long_term`、`kind=long_term`，所有长期记忆采用统一模型，不按偏好、约束、面试复盘或对话分类；
- 更新前保存历史版本，rollback 恢复最近修订，关闭或过期记录不参与召回，purge 清理到期记录及历史。
- 设置页通过受鉴权的 Backend 接口提供新增、更新、删除和清空；对话中的显式记忆命令在进入 Runtime 前由 Backend
  确定性执行并按实际结果答复。删除与更新只允许严格命中一条记录，零命中不伪装成功，多命中要求用户明确目标，避免模型口头确认或模糊匹配误删。
- 姓名新增、更正和删除采用有界自然语言规则接管；“我其实叫某人”等明确更正表达必须先完成受属主约束的真实更新，再返回成功结果，未命中规则的普通问答不得声称记忆已经变更。

- 所有读写根据受信的租户与 `X-Operator-Id` 隔离，并记录操作者、动作、结果、标识和版本。
- 记忆正文可能包含个人信息或提示注入，日志不得无必要输出全文；
- 进入 Prompt 前必须标注来源、限制长度并经过 Runtime 注入探针。

- PostgreSQL 连接和语句执行均设置超时，Embedding 请求不自动重试；配置、模型或数据库异常不会被解释为成功。
- `/health` 同时检查 Mem0 向量存储和原生 history；失败返回 HTTP 503，不调用远端模型。
- PostgreSQL 向量写入和 SQLite history 不构成跨存储原子事务；显式写入失败不能自动重放，需核验实际状态，备份和恢复必须覆盖两者。
- 历史表迁移脚本只读源表，按旧公开 ID 检查重复并复制历史，发现不完整或冲突条目时停止，不盲目覆盖。

## 验证

- 确定性测试使用真实 Mem0 SDK + Qdrant，替换 Embedding 输出以验证接口、所有权、scope、禁用/TTL 前置过滤、多次回滚、删除与历史擦除、模型错误和旧数据迁移。
- 真实效果评估使用固定中文合成集和已配置的真实 Embedding，记录逐例命中及延迟，并按固定阈值判定。
- pgvector 集成验证必须在独立数据库或评估 collection 中执行，不向真实用户分区写测试数据；Qdrant 结果不能代替 pgvector 验收。
- Harness 的普通 gate 只证明确定性契约；`AGENT_MEMORY_LIVE_EVAL=1` 额外开启真实 pgvector 质量门禁。浏览器端到端验证需实际 Backend 和 Memory 服务，不以测试替身代替。
