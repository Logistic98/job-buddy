# 多语言代码注释规范

## 注释目标

- 注释用于补充代码本身难以稳定表达的职责、协议、边界和设计理由。
- 命名、类型和结构已经足够清楚时，不以“提高覆盖率”为目的重复描述实现，也不要求为每个文件、字段、构造器、简单访问器或一行包装函数添加模板注释。

仓库自有代码的注释统一使用精简中文；协议名、类型名、配置键、标准缩写和外部工具名保留原文，避免生硬翻译影响检索和准确性。

仓库级注释审查优先回答以下问题：

- 当前模块在跨服务链路中承担什么职责，明确不承担什么职责。
- 公共入口接受什么语义的输入，返回值、异常、幂等性、权限和副作用边界是什么。
- 状态机、重试、超时、降级、缓存、并发、事务和资源释放为何采用当前顺序。
- 外部数据、凭据、日志、Trace、文件和网络内容有哪些安全约束。
- 非直观算法、兼容分支和协议映射依赖哪些不变量。

## 文件与类型说明

- Python 核心模块使用模块级 docstring 说明能力边界；仅用于导出符号的空 `__init__.py` 不需要文件说明。
- Java 的 Spring Service、Repository、Client、配置、安全组件和公共工具类使用类型级 Javadoc 说明职责。DTO 的字段语义已由类型、Bean Validation、`@Schema` 或 record component 完整表达时，不重复增加类型注释。
- Vue 组件名称、模板结构和 props 已能说明用途时，不强制添加文件头。复杂 composable、Pinia Store、SSE 解析器、富文本渲染器和跨页面状态模块应在入口附近说明状态所有权与生命周期。
- Shell 与 Harness 脚本应在 shebang 后说明用途、破坏性边界或运行前提；命令本身显而易见时不逐行解释。
- Flyway 已发布迁移是不可变资产，不为补注释修改历史迁移。配置文件、静态数据和生成文件只有在存在非直观约束时才补充说明。

## 方法与代码片段说明

公共方法出现以下任一情况时，应使用 Javadoc、docstring 或 JSDoc 描述契约：

- 跨模块、跨服务或面向扩展点调用。
- 存在副作用、事务、幂等、缓存、锁、重试、降级或资源释放。
- 返回空值、部分结果或结构化错误具有特定协议语义。
- 参数单位、范围、优先级或安全含义不能从类型和命名直接得出。
- 算法依赖稳定排序、阈值、回退顺序或兼容性不变量。

实现类覆盖接口方法且没有改变契约时，使用接口文档或 `{@inheritDoc}`，不复制同一段说明。私有方法仅在名称和结构仍不足以表达原因、顺序或边界时添加短注释。

- 关键代码片段的注释放在所解释逻辑之前，重点说明“为什么”和“不变量”。
- 禁止逐行翻译条件、循环、赋值和日志；
- 禁止用 `TODO` 代替已确定的工程边界；
- 禁止在注释中记录迭代历史、临时方案、真实密钥、个人数据或可能过期的手工快照。

## 语言约定

### Java

- 公共扩展点使用 Javadoc，并在有信息增量时写 `@param`、`@return`、`@throws`。
- Spring Bean 的类型说明应包含业务职责或安全边界，不复述 `Service`、`Repository` 等注解。
- Controller 接口语义优先由 SpringDoc 的 `@Tag`、`@Operation`、`@Parameter` 和 `@Schema` 表达，避免再写内容相同的 Javadoc。

### Python

- 模块 docstring 位于文件首个语句，概括模块边界而非文件名。
- 公共类和核心公共函数说明输入输出、失败语义及副作用；Pydantic 模型字段已经有 `description` 时不重复。
- FastAPI 路由已通过 `summary`、`description`、响应模型和状态码完整描述时，可以不添加同义函数 docstring。

### JavaScript 与 Vue

- 对外导出的复杂函数和 composable 使用 JSDoc 说明状态所有权、生命周期、异常或返回结构。
- 事件处理、SSE 拼接、快照合并、分页渲染和 HTML 安全处理应注释关键不变量。
- 模板中只为不直观的交互区域或可访问性处理添加注释，不给每个布局容器加标签说明。

### Shell

- 对删除、终止进程、覆盖文件、修改 Git 配置和启动多服务等动作明确说明作用域与保护条件。
- 对来源校验、PID 所有权、临时文件清理和失败回滚说明设计理由。

## 审查与验证

注释变更不得改变路由、权限、请求响应结构、业务调用顺序、默认配置或用户交互。交付前至少执行：

```bash
$ ./scripts/format-code.sh --check
$ git diff --check
$ ./.agent-harness/scripts/gate.sh all --quick
```

- 审查差异时确认注释与当前代码一致、没有失效路径和过度承诺，并对 Java、Python、JavaScript/Vue、Shell、配置与迁移分别记录“不需要补充”的判断依据。
- 纯注释变更不需要新增行为测试；
- 如果注释审查暴露并促成了契约或实现变更，则按实际影响同步更新测试、Harness、Eval 和主题文档。
