# 平台运行参数与动态配置

## 能力目标

- 平台设置的“运行参数”集中控制岗位推荐、Boss 检索、Agent 预算和简历管理。
- 参数保存在 PostgreSQL `platform_setting` 的 `global/settings`，保存后作用于后续请求，无需重启；
- 恢复默认会删除 `workspace` 覆盖并重新应用 Backend 启动时加载的部署默认值。

环境变量和 `application.yml` 负责定义 Backend 启动时的默认值；服务地址属于部署边界，始终以环境配置为准。

加载完成后，除只读服务地址外，持久化值是界面所列字段的唯一运行期值，业务链路不得再次读取同名环境变量覆盖。未展示的工具超时、重试、页间延迟、Token 上限和候选总评分上限仍由部署配置控制。

## 参数契约

| 分组       | 参数                              |  默认值 |    范围 | 实际作用点                                                      |
| ---------- | --------------------------------- | ------: | ------: | --------------------------------------------------------------- |
| 岗位推荐   | `maxJobsPerRecommend`             |      15 |    1–30 | 推荐卡片每批上限、质量门达标后的提前停止数量                    |
| 岗位推荐   | `recommendOverfetchFactor`        |       5 |    1–10 | 候选评估池大小，和每批展示数量相乘后受 `maxJobsPerScoring` 限制 |
| 岗位推荐   | `minimumRecommendedMatchScore`    |      60 |   0–100 | 简历匹配推荐质量门；候选不足时继续检索和评估，不降低门槛        |
| Boss 检索  | `bossSearchMaxPages`              |       2 |     1–5 | 首轮候选预热和“换一批”补充时单次最多抓取页数                    |
| Boss 检索  | `bossSearchMaxPageDepth`          |       5 |    1–10 | 同一检索条件允许深入的最大 Boss 页码                            |
| Boss 检索  | `bossSearchCacheTtlMinutes`       |      30 |  1–1440 | 用户级候选池缓存有效期                                          |
| Boss 检索  | `bossSearchCooldownMinutesOnRisk` |      30 |  1–1440 | Backend 识别验证码、限流或风控信号后的暂停时长                  |
| Agent 预算 | `runtimeMaxTurns`                 |      12 |    1–20 | Backend 发给 Runtime 的 `budget.max_turns`                      |
| Agent 预算 | `runtimeMaxToolCalls`             |      20 |    1–30 | Backend 发给 Runtime 的 `budget.max_tool_calls`                 |
| Agent 预算 | `runtimeMaxFailures`              |       3 |    1–10 | Backend 发给 Runtime 的 `budget.max_failures`                   |
| 简历管理   | `maxResumeBytes`                  | 5242880 | 1–20 MB | Backend 接收简历文件前的字节数校验                              |
| 简历管理   | `resumeWriterVersionLimit`        |      30 |   5–100 | 版本列表上限和新建版本后的历史裁剪数量                          |

- 默认 Agent 预算与 Runtime 保持 12 轮、20 次工具调用和 3 次连续失败。
- 推荐每批 15 个、候选倍率 5、部署级总评分上限 80；
- 系统沿缓存游标继续抓取未访问页面，直到展示数、评分上限、最大深度或上游耗尽。
- 最低推荐分为 60，并同时要求置信度不为 low、建议不是谨慎/不建议/证据不足。
- Boss 单次最多 2 页、最大深度 5 页、缓存和风险冷却均为 30 分钟。

## 加载、保存与并发可见性

- Backend 初始化时读取持久化配置，经过白名单、整数解析和范围归一化后更新运行快照。
- 配置表短暂不可用时保留部署默认并由健康轮询重试，不阻断启动；
- 显式查询、保存和恢复仍返回数据库错误。
- 三类操作使用同一归一化，保存接口返回实际生效值。

动态字段需要跨 Servlet、SSE 与候选池线程可见。消费者在新请求或任务开始时读取当前值，已开始任务固定使用启动时的预算和候选规模，避免执行中途语义漂移。

## 风险边界

平台设置不能覆盖工具层和外部服务自身的安全限制。

- Boss CLI 的小时配额、抖动、超时和上游冷却可比 Backend 更严格，Runtime 的 Token 上限和工具权限也保持最终约束。
- 界面只能设置 Backend 发起任务时的业务预算，不能授予权限、绕过风控或放宽隔离。

- `maxJobsPerScoring`、`runtimeMaxTokens`、`bossSearchTargetCandidates`、`bossSearchPageDelayMillis` 和工具超时不在普通运行参数界面展示，它们是部署级安全边界。
- 新增可编辑参数时必须同时补齐前端范围、后端白名单与归一化、真实消费点、文档和行为测试，禁止只增加表单字段。

## 服务健康监控

- “服务监控”展示 Runtime、Intent、Memory、Tool、Eval 和 Sandbox 六个下游的当前状态与最近记录，Backend 按各自地址请求 `/health`。
- `sandboxUrl` 独立存在；
- 服务地址也供实际客户端使用。

- 六个服务地址始终以 Backend 启动时的环境配置为权威来源，不写入 PostgreSQL，也不允许平台设置覆盖。
- 非容器模式从根 `.env` 的 `AGENT_*_URL` 注入 loopback 地址；
- Compose 从 `JOB_BUDDY_INTERNAL_*_URL` 读取 `agent-runtime`、`agent-intent` 等内部 DNS 并注入各容器。
- Backend 启动加载设置时会移除历史持久化地址；
- 界面只读展示实际生效地址，仍允许调整连接与读取超时。

- 健康监控是旁路能力，单个下游不可达只记录失败摘要，不拖垮 Backend 或普通接口；
- Backend 首先按 HTTP 状态判断可达性：非 2xx 记为不可用；2xx 响应若包含统一响应
  `data.status`（或直接健康对象的 `status`），则 `UP`、`healthy` 记为运行成功，
  `DEGRADED` 记为运行降级且不计入运行成功率，降级原因优先采用 `reason` 展示；明确返回但不受支持的业务状态记为未知，也不计入运行成功率；
- 为兼容旧式健康端点，2xx 响应正文为空、不是 JSON 或缺少业务状态时仍记为运行成功；
- 业务真正需要该服务时仍按自身策略失败，例如 Sandbox 不可用时判题关闭而不回退宿主机。
- 监控不得保存内部令牌、数据库连接串或敏感正文。

## 验证方法

后端测试应覆盖默认值、越界归一化、保存后运行期配置立即更新、恢复默认、Runtime 请求预算、岗位候选规模与推荐阈值、Boss 分页和缓存边界、简历上传大小、版本裁剪，以及六个下游服务的健康历史。

- 前端测试覆盖默认回退、输入范围、`workspace` 作用域、Sandbox 地址和恢复确认。
- 交付前执行 Backend 与 Frontend Gate，并在浏览器中完成修改、保存、刷新回显和恢复 12 项默认值；
- 服务监控还要验证 Sandbox 独立显示成功、失败或未配置，并验证 HTTP 200 +
  `data.status=DEGRADED` 显示“运行降级”、保留原因且不计入运行成功率。
